# Integrações externas

Esta página lista integrações chamadas pelo backend. O app não mantém proxy público nem API de servidor próprio.

## AniList

- GraphQL em `https://graphql.anilist.co`.
- Fornece descoberta (Em alta e Temporada atual), títulos em idiomas diferentes, sinônimos, IDs de AniList/MAL, capa/banner, score, ano de lançamento, formato, quantidade de episódios e descrição. A busca já solicita esses metadados na consulta GraphQL em lote; cards de provedores só os recebem quando a identidade AniList é inequívoca. A chave de cache de títulos inclui versão para renovar entradas anteriores que não armazenavam ano e formato.
- A Home tenta primeiro a AniList. Quando a consulta falha e não há resposta atual, usa o catálogo público do MyAnimeList para ranking por popularidade e temporada atual; o aviso da Home identifica a fonte alternativa. Se as duas origens estiverem indisponíveis, o cache local ainda válido de uma delas pode ser exibido.
- Busca e lookups são limitados por `Gate` e cacheados. Lookups por títulos podem ser agrupados/coalescidos e há limite de concorrência definido em `Metadata`.
- Tradução de sinopse, quando necessária, consulta o endpoint público `translate.googleapis.com/translate_a/single` configurado para `pt-BR`; erro de tradução não é identidade de anime e não deve impedir reprodução.
- Login abre o navegador do sistema e recebe o retorno em `http://localhost:9742/`, valida um `state` aleatório e expira após dois minutos. O fluxo implícito é suportado pela API; o token longo (até um ano) fica no cofre de credenciais do sistema e não é enviado à interface.
- Depois que o MPV termina, o app consulta a entrada atual e só envia progresso via `SaveMediaListEntry` se houve EOF natural ou se a posição chegou a 80% da duração conhecida. Uma interrupção antecipada não avança a lista; a leitura antes da gravação impede que um episódio repetido regrida a lista ou reabra uma obra concluída. O envio usa o AniList ID canônico associado à obra; sem ID inequívoco, nada é sincronizado.

## MyAnimeList (MAL)

- OAuth/API base: `myanimelist.net/v1/oauth2` e `api.myanimelist.net/v2`.
- A descoberta pública usa `GET /anime/ranking?ranking_type=bypopularity` e `GET /anime/season/{year}/{season}?sort=anime_num_list_users`, com capa, títulos alternativos, tipo, episódios, nota, ano e sinopse. As chamadas usam o Client ID público do aplicativo, sem exigir que a pessoa conecte uma conta. A documentação é a [referência oficial da API v2](https://myanimelist.net/apiconfig/references/api/v2). O ranking por popularidade é uma aproximação do “Em alta” da AniList; cada resultado mantém o MAL ID e não recebe AniList ID por inferência de título.
- A descoberta usa cache local de uma hora, com retenção máxima de sete dias. Se apenas uma prateleira responder, a Home mostra os itens disponíveis e um aviso; se ambas falharem, o cache salvo é usado quando ainda existir.
- O Client ID identifica o cadastro OAuth do AnimeCaos e é uma configuração interna da aplicação; **não documentar o valor aqui nem incluir Client Secret**. Ele não é uma credencial da conta MAL do usuário e não aparece em Configurações.
- O login abre callback local em `http://localhost:9743/`, valida `state`, troca o `code` com PKCE `plain` e expira em dois minutos. A troca/refresh autenticam o cliente por HTTP Basic (`client_id:` para clientes públicos; `client_id:client_secret` se a aplicação registrada exigir segredo). O perfil usa `/v2/users/@me`; sincronização consulta `/v2/anime/{id}?fields=my_list_status` antes de enviar `PATCH /v2/anime/{id}/my_list_status` com status e número de episódios assistidos. O progresso não diminui e uma entrada concluída permanece concluída.
- O Client ID é selecionado pelo backend e não pode ser alterado pelo usuário. Um segredo salvo anteriormente no cofre do sistema pode continuar sendo usado pelo backend em instalações existentes; a aplicação não inclui segredo no executável e a interface não solicita credenciais de desenvolvedor. O refresh do token ocorre antes de chamadas quando o acesso está perto de expirar.
- A tela de Configurações permite conectar/desconectar as contas e mostra o perfil; a rota Contas oferece as mesmas ações. As imagens locais `frontend/public/anilist.ico` e `frontend/public/myanimelist.ico` são favicons obtidos dos domínios oficiais e evitam requisições externas para identificação visual.
- Os testes locais cobrem a mutation GraphQL do AniList, o PATCH do MAL, leitura prévia e HTTP Basic na troca/renovação de token usando servidores de fixture. A verificação do endpoint MAL iniciou o fluxo de autorização, mas a troca sem segredo retornou `invalid_client`; por isso o login MAL de primeira conexão continua pendente. Antes da distribuição, o cadastro OAuth precisa oferecer fluxo público compatível com desktop ou usar um serviço intermediário seguro; não se deve pedir ao usuário as credenciais de desenvolvedor.

## MangaDex

- API base `https://api.mangadex.org`; arquivos de capa em `https://uploads.mangadex.org/covers`.
- A política oficial exige crédito à plataforma e aos grupos de tradução, atendimento a pedidos de remoção de grupos e proíbe anúncios ou serviços pagos no aplicativo que consome a API.
- Pesquisa de título consulta inicialmente tradução `pt-br`; em seguida tenta busca sem filtro de idioma se não encontrou itens.
- A página de descoberta combina o ranking `followedCount`, a ordenação `latestUploadedChapter`, o status `ongoing` e as tags do grupo `genre`. Os nomes das categorias são apresentados em português quando há tradução local e os filtros enviam o ID oficial da tag.
- A descoberta é limitada a conteúdo safe/suggestive e fica em cache por 15 minutos, com fallback máximo de seis horas; consultas por categoria usam o mesmo prazo. As três prateleiras de obras são solicitadas em paralelo e respeitam o gate de 250 ms entre requisições.
- MangaDex não fornece uma classificação sazonal confiável de mangás. “Em alta” significa obras com capítulo enviado mais recentemente; “Em publicação” usa o status explícito da API. A tela não infere uma temporada de anime para uma serialização de mangá.
- Capítulos percorrem `pt-br`, `en`, `es-la`, `es` por padrão; o frontend também permite pedir um idioma específico. A paginação usa lotes de 500.
- Páginas vêm de `/at-home/server/{chapterID}`: `data` é a qualidade original e `data-saver` é a alternativa comprimida. O leitor registra ambas no gateway e oferece repetir a consulta ao `at-home` se uma atribuição falhar, sem persistir URLs temporárias.
- A montagem das páginas aceita resposta com apenas `data-saver`, exige base HTTP(S) e hash válido, e descarta nomes vazios. Conteúdo é compactado em CBZ para leitura offline.
- O Gate do serviço define intervalo mínimo de 250 ms por requisição nesta implementação.
- A tela local oferece busca sob demanda, capítulos por idioma, progresso retomável, leitor contínuo/paginado e direção RTL/LTR. MangaDex é creditado na tela e o grupo de tradução é mostrado em cada capítulo quando o relacionamento vier na resposta da API.

## Discord Rich Presence

O link de conta usa OAuth Authorization Code com `identify`, `state` aleatório, PKCE S256 e verificação do emissor `https://discord.com`. O retorno local é `http://127.0.0.1:9744/`, com timeout de dois minutos; essa URI exata precisa estar registrada em OAuth2 → Redirects no Developer Portal. Para cliente público nativo, habilite `Public Client`; o guia Discord demonstra a troca de token através de `Client::GetToken`. O adaptador Go envia a troca Authorization Code + verifier ao endpoint HTTP e está coberto por fixture, mas esse caminho ainda precisa ser confirmado contra uma aplicação real antes de release. Os tokens ficam no cofre do sistema operacional e o perfil `/users/@me` fornece nome, ID externo e avatar. Recusar a autorização encerra o fluxo imediatamente.

O vínculo de conta identifica o perfil Discord e oferece atualizar/desconectar; ele **não** registra episódios assistidos. O Discord não disponibiliza `activities.read` nem `activities.write` para apps comuns, então AniList e MyAnimeList continuam responsáveis pelo progresso. O login Discord também é separado da presença e não é requisito para enviá-la.

Enquanto a opção Rich Presence estiver ativa e o Discord Desktop estiver aberto, o processo MPV publica pelo IPC local o nome `AnimeCaos`, anime, temporada/episódio e tempo decorrido; durante pausa o contador congela e, ao parar, a atividade é removida. O texto de estado e o relógio são atualizados com base no estado real do player, inclusive após seek. Os arquivos de IPC ficam em `discord_windows.go` e `discord_unix.go`; conexão, heartbeat, reconexão e limpeza ficam em `discord.go` e no serviço. O Developer Portal precisa ter o nome e o ícone da aplicação definidos e uma arte Rich Presence com a chave `logo`, usada como imagem principal.

A tela de Configurações mostra o símbolo Discord, o estado do controle de presença e os cartões de perfil das três contas. A imagem local `frontend/public/discord.svg` usa o símbolo disponibilizado nas diretrizes oficiais da marca. Fixtures cobrem PKCE, validação do callback, armazenamento seguro, perfil, cancelamento e payload IPC; autorização por conta real e presença em um cliente Discord real ainda não foram verificadas nesta rodada.

## Atualizador

- Builds de distribuição Windows e AppImage Linux iniciam uma consulta a `https://api.github.com/repos/henriqqw/animecaos/releases/latest` ao abrir o app. A consulta tem limite de 8 s; sem rede, pacote de desenvolvimento e builds não suportadas seguem para o app sem instalar nada.
- Para uma versão numericamente superior, escolhe o ZIP Windows `windows-amd64.zip` ou AppImage Linux x86_64 e baixa `SHA256SUMS`. Verifica o SHA-256 do pacote antes de registrar sua validação local e instalá-lo; o progresso é enviado à barra da splash.
- A splash espera o resultado da checagem/download. Após a validação, o helper roda com o diretório de trabalho fora da pasta instalada, espera o processo antigo fechar e aguarda os processos que ainda executam arquivos do pacote. No Windows, se o WebView2 fixo continuar aberto após três segundos, o helper encerra apenas os processos do runtime empacotado antes de trocar o diretório e abrir a versão nova. Se a espera atingir o limite, o log identifica processos detectados executando da instalação. Falhas na extração/troca removem o stage temporário; o helper valida caminhos do ZIP, rejeita symlinks/duplicatas e limita o conteúdo descompactado. Dados do usuário ficam fora do pacote.
- Flatpak é identificado como gerenciado pelo sistema; `wails dev` não participa do fluxo. Configurações ainda oferece checagem, download e instalação manuais.
- A edição Windows da release histórica `v2.0.0` ainda tem um atualizador Python que detecta a release 3.x e solicita confirmação antes de copiar o ZIP para a instalação existente. Após a migração, o atualizador Go/Wails aplica as próximas versões automaticamente. O atualizador legado não confere o SHA-256; o novo confere. A edição Flatpak antiga não instala o AppImage e requer migração manual. Atualizações ponta a ponta devem continuar sendo exercitadas pelos smoke tests Windows e AppImage.

## Configuração e credenciais

Tokens OAuth e um Client Secret MAL legado ficam em `internal/securestore`, que delega ao Windows Credential Manager no Windows e ao Secret Service via D-Bus no Linux. A integração exige um cofre de credenciais disponível; se ele estiver indisponível, a chamada mostra erro e não grava credenciais no SQLite como fallback. Em instalações anteriores, a primeira leitura migra a credencial do bucket `auth`, grava no cofre e remove a cópia SQLite com `secure_delete`, checkpoint e `VACUUM`. O frontend não recebe o segredo nem seu estado de configuração; um segredo legado já salvo continua disponível ao backend. `Logout` apaga o token OAuth, sem alterar essa credencial antiga. Cópias antigas do diretório de dados e backups feitos pelo usuário não são alterados. Nunca registrar valores de tokens, segredos ou URLs assinadas. Consulte [dados e migrações](DATA_AND_MIGRATIONS.md).
